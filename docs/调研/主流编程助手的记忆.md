# 主流编程助手的记忆：谁写、何时读、从哪里接入

核对日期：2026-11-21。范围是开发者实际使用的编程客户端。下文区分厂商文档、公开源码和本机运行结果。它们的“记忆”至少有三种意思：每次开工都读的规则、从过去工作中留下的经验、可以继续的聊天记录。三者的用途和读取时机不同。

## 1. Claude Code

- **规则。** 用户级 `~/.claude/CLAUDE.md` 和项目级 `CLAUDE.md` 等说明提供常驻约定。项目默认在找不到项目 `CLAUDE.md`、`.claude/CLAUDE.md` 或 `CLAUDE.local.md` 时回退到 `AGENTS.md`；用户级 `~/.claude/CLAUDE.md` 不会阻止项目回退。部分版本和设置可以让两种文件同时加载。
- **自动记忆。** Claude 在工作过程中判断哪些纠正或经验值得留下；也可以直接对它说“记住……”。默认写进本机 `~/.claude/projects/<项目>/memory/`。开启自动记忆后，启动只读入口 `MEMORY.md` 的前 200 行或 25 KB，先到哪个算哪个；详细主题文件按需打开。同一仓库的多个工作树共享这份原生记忆。
- **怎么查看。** `/memory` 可以看已识别的说明、打开笔记、开关自动记忆。记忆和规则都会作为上下文提供给模型；文档提示不保证模型每次遵守。
- **给 smem。** 可以保留全局 `CLAUDE.md` 首行 `@AGENTS.md`。这是同目录相对导入，指向 `~/.claude/AGENTS.md`，不会指向 `~/.codex` 或当前仓库。需要项目兼容时在项目这一层单独处理。不要接管它会自行维护的 `MEMORY.md`。
- [Anthropic 官方：规则、自动记忆与导入](https://code.claude.com/docs/en/memory) · [项目说明的选择顺序](https://code.claude.com/docs/en/memory#agents-md)

## 2. Codex CLI

- **规则。** 启动时，从 `CODEX_HOME` 的用户说明读到当前 Git 项目的工作目录。每层有有效的 `AGENTS.override.md` 就优先用它，再考虑 `AGENTS.md`。新增规则后应开新会话。团队必须遵守的约定，官方建议保留在项目说明中。
- **自动记忆。** 当前文档说明本机记忆默认关闭。打开后，可以用 `/memories` 分别决定这次聊天能否使用既有记忆、能否给以后贡献记忆。后台挑选达到条件且已闲置的会话，先从每段提取有用事实，再进行合并整理；刚聊完不会立即产生可供下一工具读取的记录。
- **存储。** 新 CLI 配置默认使用 `memories_v2/`；已有 `memories/` 的配置默认继续用旧目录，也可显式选版本。官方提醒这些文件是工具生成的状态。原生记忆还有版本、开关、配额和会话筛选条件。
- **给 smem。** 复用能稳定加载的说明；经验形成时立即用命令落盘。另一工具马上能查到，且独立于 Codex 何时整理聊天、是否开了原生记忆。不要把两个版本的目录绑定成公共接口。
- [OpenAI 官方：本地记忆与开关](https://learn.chatgpt.com/docs/customization/memories) · [用户与项目说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md) · [固定版本的写入流程源码说明](https://github.com/openai/codex/blob/583ec348cf9007361d09513c716549c41d4d8128/codex-rs/memories/README.md)

| **Cursor 编辑器** | 项目 `AGENTS.md` 或 `.cursor/rules/*.mdc` 会给 Agent 提供说明；用户级规则在设置中编辑。1.0 发布记录曾提供按个人和项目保存的 Memories 测试功能；当前规则文档未给出可当公共接口的原生记忆文件。不可从老公告推断所有当前用户都开着它。[当前规则](https://cursor.com/docs/rules) · [1.0 记忆公告](https://cursor.com/changelog/1-0#memories) | 直接复用项目根 `AGENTS.md`，省掉第二份内容相同的 Cursor 规则。不开编辑器数据库。 |

| **OpenCode** | 有全局与项目 `AGENTS.md`，同目录无此文件可回退到 `CLAUDE.md`。官方说明讲的是规则加载；本次未找到可当跨工具长期记忆接口的官方承诺。可恢复的会话不能据此当作持续积累的事实库。[官方规则及回退顺序](https://opencode.ai/docs/rules/) | 沿用项目说明和全局规则；如果全局本就在借用 Claude 的说明，保留这个关系，不改配置。 |

## 4. 能借用什么，哪些东西可以省

1. **借 Claude 的按需读。** 默认只教一条查写规则。笔记积累再多，启动都不塞进对话。借 Copilot 的出处思路：查到结论就带本地文件和行号，变化快的事实回到代码核对。
2. **借 Gemini 的分范围。** 一个项目怎样部署和一个人习惯怎样工作是两类信息。写入默认当前项目，个人偏好显式写全局。不能因为用户在另一个目录就偷偷升级成全局。
3. **省掉后台整理。** 无需常驻进程、模型服务、聊天抓取、数据库和定时任务。Markdown 直接查，首版连索引文件都不建。拼写与同义词不会自动匹配，这是有意接受的代价。
4. **迁移提示词有官方先例。** [Devin 的迁移指南](https://docs.devin.ai/onboard-devin/migrate-from-other-agents)也让用户贴一段提示词，保留源文件、略过重复和密钥。smem 让原助手整理它已经能访问的长期事实，确认后逐条写共享库。它不能替用户取得其他工具的私有权限。

## 5. 验证口径

官方文档和公开源码说明“产品设计上怎样工作”。本项目另用真实 `mem` 进程验证读写、范围和迁移边界；用本机 Codex CLI 0.157.0 的 `debug prompt-input` 检查实际提交给模型的输入：含查写用法，不含测试记忆正文。已写配置不等于模型一定调用命令。各家真实模型在不提醒时主动查询的成功率，仍需真实任务验证。
