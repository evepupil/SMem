# Claude Code 与 Codex：无提醒接力

2026-11-21，Windows。本次验证两件不同的事：命令能否可靠地操作同一条 Markdown，以及一个全新助手会不会自己使用这些命令。

## 同题前后比较

| 写入 → 接手 | 旧版成功写入 | 旧版读到并用对 | 新版成功写入 | 新版读到并用对 |
| --- | ---: | ---: | ---: | ---: |
| Claude Code → Codex | 5/5 | 0/5 | 5/5 | **5/5** |
| Codex → Claude Code | 1/5 | 0/5 | 3/5 | **3/5** |

旧版来自 `be6277e`（只包含最初的查写功能）。最终两组各 10 例，客户端均正常完成，未剔除失败样本。Claude Code 与 Codex CLI 均使用显式指定的低成本 `custom/gpt-6-luna`。这是对两个真实客户端的实验，不能外推为 Anthropic 和 OpenAI 原厂模型的对比。

写入方收到一条项目长期约定，每例的放行人代号不同；接手方只看到「准备一份本项目的上线交接单。在回复中分三行填写：项目、放行人、下一步。没有依据的字段写‘未确定’。」没有告诉它记忆在哪，也没有在题面中提示查找。两端各用新的用户配置、会话与合成仓库，只传输共享库的 Markdown，不传写入方的历史、说明改动或其他项目文件。旧版和新版使用同一批代号、同一客户端版本、模型、题面、权限和评分程序。

计分要求：观察到写入方成功调用添加且卡片正文含代号，接手方成功通过命令取到含代号的正文，最后一条回复中交接单的“放行人”字段填写正确。说“已记住”、猜中、仅凭文件名或中间消息都不算。旧版有一次答对但没有共享命令返回正文的证据，按预定条件计失败。最终新版两次失分均在 Codex 写入侧（第 1、4 例）：它执行了搜索但没有执行添加；Claude 接手时库里没有答案。其余八例都查到并用对。**最终成绩 8/10；反向只有 3/5，尚未达到每方向至少 4/5 的门槛。**

[旧版逐例结果](数据/旧版接力.json) · [新版逐例结果](数据/新版接力.json) · [复跑方法](../../scripts/bench/README.md)。两个报告记录了案例集与运行程序的摘要、二进制摘要、模型、客户端版本、每次查写及结论。报告仅含合成资料。

## 操作与对照

- 命令级：更正、单条忘记、分页翻看、展开原文、同目录两进程竞争、手改后旧引用拒绝、保留相邻笔记均通过。`go test -race ./...` 包含独立 Windows 子进程测试。
- 用户级：第一次纠正虽然原位更新，新正文也保留了旧放行人，导致另一助手翻看时同时看见旧值。补充“只写现行结论、历史交给 Git”，并在更新后回显正文。最终真实流程中 Codex 改为新人，文件位置未变、旧值消失、相邻记录保留；Claude 列表并展开验证，忘掉后 Codex 在新会话确认不再返回，换项目也没有串读。[首次结果](数据/自然改删首轮.json) · [残留原因](数据/自然改删复核.json) · [最终完整流程](数据/自然改删交付.json)。
- 未配置专用适配的 Pi：只收到可粘贴的通用用法。实际查到合成放行人、填对并成功写入另一条长期约定。[结果](数据/通用客户端.json)。
- 原生对照：同品牌连续两次新会话，关掉 smem，允许原生工具工作。Claude 的接手方填对 5/5，其中 4 次在接手前检测到自动记忆文件，**5 次项目内也出现了答案**，无法把成功单独归因于原生记忆。Codex 的立即接手填对 0/5，接手前也未检测到已生成的原生记忆，不能据此判断它闲置整理以后的效果。[结果](数据/原生对照.json)。

## 环境校准

Windows 默认临时目录存在真实用户的上层 Claude 说明，且默认策略曾拒绝合成命令。早期运行只用于定位环境，没有纳入正式计分。正式组改到没有上层说明的独立目录；先让两端各自实际写一条、查回原文，确认终端权限。只为合成工作区配置 `mem` 执行许可，没有更改用户实际客户端设置。Codex 的某些干净配置在这个环境里还会启动插件克隆并发生超时；正式可比组两边均关闭无关插件及子代理。

中间用法明确了长期约定可以直接记，无需改项目配置或请求二次批准，一轮达到 9/10；其中一次接手只查了一组没有命中的词。随后发现自然纠正仍会把旧值留在正文。修正这个问题后，使用最终回复评分从头重跑旧版和交付版，得到上表。没有挑中间最好的一轮作为发布成绩。[中间版结果](数据/中间版接力.json)。下一步优先观察 Codex 在哪些表达下只查不写，增加新题型再评估稳定性；不针对特定领域或人名硬编码。
