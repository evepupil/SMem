# SMem 记忆格式与行为规范（Claude Code 兼容标准）

## 1. 目录布局

每个作用域目录（`~/.smem/global/` 或 `~/.smem/projects/<repo-id>/` 或 `<repo>/.smem/memory/`）采用完全一致的扁平双层布局：

```text
<memory-dir>/
├── MEMORY.md                     # 自动维护的入口索引（硬控 ≤ 200 行 / 25KB）
├── user_backend_profile.md       # 主题文件 1
├── feedback_terse_output.md      # 主题文件 2
├── project_release_owner.md      # 主题文件 3
└── reference_ops_dashboard.md    # 主题文件 4
```

## 2. 主题文件格式

主题文件为 UTF-8 Markdown，顶部包含 3 个标准 YAML Frontmatter 字段：

```markdown
---
name: 生产发版审批人约定
description: 涉及生产环境发布、上线交接单或部署审批流程时触发
type: project
---

本项目每次生产发版前必须由小周审批放行，再执行 `scripts/deploy.sh`。

**Why:** 2026-11-23 起由小周接替原负责人把关 checkout 服务生产发布。
**How to apply:** 准备上线交接单或部署步骤时，固定填写小周为放行人。
```

### 字段约定

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| `name` | 必填，单行简短标题 | 人类与索引可读的唯一主题名 |
| `description` | 必填，单行触发说明（建议 ≤ 120 字） | 写成**触发条件**而非空泛标题，供 LLM 判断何时读取全文 |
| `type` | 必填，四选一 | `user`、`feedback`、`project`、`reference` |

兼容规则：人类手写的无 Frontmatter 普通 `.md` 文件同样可被读取、索引与检索（自动以首个标题或文件名作为 `name`、首段摘要作为 `description`）。

## 3. 四种记忆类型与作用域归属

| `type` | 含义 | 推荐作用域 | 写作要点 |
| --- | --- | --- | --- |
| `user` | 开发者角色、技术背景、语言与沟通偏好 | `global` | 客观描述，不臆测 |
| `feedback` | 纠错与明确确认的工作规范（“别这样做 / 以后都这样做”） | 跨项目进 `global`，仅限单项目进 `project` | 强烈建议包含 `**Why:**` 与 `**How to apply:**` |
| `project` | 代码与 Git 历史推导不出的项目决策、约束、审批人、环境坑点 | `project` | 相对时间必须转为绝对日期（如 `2026-11-23`） |
| `reference` | 外部看板、监控、文档库、工单系统等指针 | `project`（个人通用放 `global`） | 写清系统用途与访问入口，不存凭证 |

## 4. 明确“不该记什么”（高信噪比纪律）

- **不记代码/Git 可直接查到的内容**：目录结构、函数实现、已有配置项、最近 Commit 历史。
- **不记临时过程与一次性要求**：本次调试日志、临时报错栈、“这一次用 npm”。
- **不记已写在 `CLAUDE.md` / `AGENTS.md` 中的静态规则**。
- **严禁记录密钥、Token、私钥、密码与敏感个人资料**（SMem 写入前会强制扫描拦截）。

## 5. `MEMORY.md` 索引规范

- 每条主题记忆占一行：`- [<name>](<file.md>) — <description>`。
- 硬性预算：**200 行或 25KB**（先到为准）。超限时 SMem 不静默截断，而是明确提示超出条数，引导调用 `memory_search` 或执行 Dream 整理。

## 6. 保鲜、更正与遗忘规范

- **相对年龄（`memoryAge`）**：读取记忆时按文件修改时间转换为 `today` / `yesterday` / `N days ago`；超过 1 天自动附加核对提醒——**记忆是历史观察，涉及代码/文件/命令行为前先核对当前仓库事实**。
- **现行真相原则**：更正已有记忆必须先读取最新 `etag`，原位替换为**仅含现行结论**的正文，不得把被淘汰的旧值或更换经过留在正文中污染检索（历史交由 Git 保留）。
- **四阶段 Dream 整理**：`Orient`（摸底检查）→ `Gather`（汇总重复/过期/冲突）→ `Consolidate`（绝对日期化、合并去重、移除失效项）→ `Prune & Index`（重建 ≤ 200 行 `MEMORY.md`）。
