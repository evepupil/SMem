# 需求设计

**产品目标：** 换编程助手后，仍能查到上一个助手留下的持久经验。使用者不需要重复交代个人习惯，也不用维护多份内容相同的项目笔记。

## 已明确的边界

1. 全局和项目两层。Markdown 是唯一事实来源，人和 Git 都能直接处理。每个助手经过同一个 CLI 读写。
2. 接入入口是一小段用法，核心只有“开工先查，有持久结论先记”。现有说明、原生记忆和旧聊天都保留。Claude 的同目录导入需单独处理。
3. 旧资料由有权读取它们的旧助手整理。提供一段任何用户都能转发的迁移提示词，分类、确认后才入库。
4. 历史、审计、冲突、撤销和跨设备同步交给 Git。不托管用户数据。

## 首版实现选择

一条新增记忆一个文件，也能检索人手写的主题文件。只做初始化、搜索、添加、打印迁移提示四件事。默认范围是当前 Git 仓库；没有仓库时只提供全局读和显式全局写。首版不做后台服务、智能总结、向量检索、用户系统或强制拦截。

## 如何判断有用

一条在 A 中形成的、代码里推不出来的项目结论，B 接手时能自己查到并用对；换到不相关项目后不再出现。软件能查到和模型会主动查分开验证。参见[路线图](roadmap.md)。
