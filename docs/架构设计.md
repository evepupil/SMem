# SMem v2 架构设计

## 1. 设计原则

SMem v2 以 Claude Code 的生产级记忆机制为蓝本，坚持以下五条硬约束：

1. **零数据库，纯 Markdown 真相源**：不引入 SQLite、向量库或常驻后台服务。每个作用域目录内仅存放 `MEMORY.md` 索引和主题 `.md` 文件。人类编辑器、Claude Code 原生工具、`git pull` 与 SMem MCP/CLI 的任何改动立即互见，绝无索引不同步问题。
2. **100% 兼容 Claude Code 记忆格式**：沿用 3 字段 YAML Frontmatter（`name`、`description`、`type`）、4 分类（`user`、`feedback`、`project`、`reference`）、`MEMORY.md` 200 行 / 25KB 索引预算与 `memoryAge` 相对年龄防陈旧提醒。
3. **极简 2 层作用域**：只保留 `project` 与 `global`，避免多作用域造成模型写入选择困难。`project` 默认落在 `~/.smem/projects/<repo-id>/`（零污染团队仓库且自动跨 Git Worktree 共享），并支持通过 `smem share push/pull` 按需选择性同步到 `<repo>/.smem/memory/` 或通过 `--shared` 直接使用仓库目录。
4. **LLM 原生语义召回**：依靠严格的“不记什么”信噪比控制，把单库规模保持在几十至百余条内；会话启动即由 Hook/MCP 呈现精简 `MEMORY.md` 索引，让活跃模型自己根据 `description` 做语义判断并按需 `memory_read`，辅以毫秒级纯内存关键词搜索兜底。
5. **跨工具确定性可靠**：通过 **MCP（5 个结构化工具）+ 超轻量 Hooks（< 5ms）+ `AGENTS.md` / `SKILL.md` + CLI** 消除提示词“忘查”与“只查不写”问题，并配备跨平台 OS 文件锁、`etag` 乐观并发校验与确定性密钥拦截。

## 2. 分层模块结构

```text
cmd/smem/            单二进制 CLI / MCP / Hook 入口
internal/
  workspace/         Git Repo / Worktree 归一化指纹、2 层作用域路径与共享模式解析
  guard/             确定性密钥/凭证扫描、`<private>` 剥离、路径穿越与符号链接防护
  memdir/            Claude 兼容双层记忆引擎：Frontmatter 编解码、MEMORY.md 原子同步、
                     OS 文件锁、etag 乐观锁、memoryAge 保鲜、纯内存代码/中文分词搜索、check/rebuild
  mcp/               零依赖 JSON-RPC 2.0 MCP stdio 服务器（5 工具 + 1 Resource + 1 Dream Prompt）
  hooks/             Claude / Codex / Cursor / Gemini 统一生命周期 Hook 路由与意图检测
  adapters/          多工具自动探测、原子配置补丁（JSON/TOML/Markdown）、自动备份回滚、
                     AGENTS.md / SKILL.md 生成、原生记忆导入（Claude/Codex/Cline/Dir）与 repo share 同步
  cli/               人类与脚本命令行接口（支持 --json）
```

## 3. Claude Code 双模式协同

- **`native`（默认，面向主力 Claude Code 用户）**：在 `.claude/settings.local.json` 中将 `autoMemoryDirectory` 指向 SMem 项目目录，保留 Claude Code 原生 Auto Memory、`extractMemories` 与 `/dream`；SMem 通过 Hook 与 MCP 补齐跨项目 `global` 记忆，同时其他所有 AI 编程工具通过 SMem 读写同一份项目与全局目录。
- **`managed`（全托管模式）**：在 `.claude/settings.local.json` 中设置 `autoMemoryEnabled: false`，使 Claude Code 与所有其他工具完全走同一条 SMem MCP + Hook 写入管线（统一密钥拦截与 `etag` 校验）。

## 4. 并发、安全与自愈机制

- **跨平台 OS 文件锁**：Unix 采用 `flock`，Windows 采用 `kernel32.LockFileEx`，配合同目录临时文件 `fsync` + 原子替换，不依赖底层卷硬链接支持。
- **乐观并发（`etag`）**：每次读取返回当前文件字节的 12 位 SHA-256 摘要；更新或删除必须携带匹配 `etag`，外部已修改时拒绝盲写并要求重新读取。
- **非静默超限提示**：`MEMORY.md` 接近或超过 200 行 / 25KB 时，明确输出未展示条数并提示使用 `memory_search` 或 `dream` 整理，绝不静默丢弃底部条目。
- **自动自愈发现**：即使外部工具（如 Claude Code 原生 Write 或人类）直接新建了主题 `.md` 但未登记进 `MEMORY.md`，`memory_index` 仍会自动发现并列出这些未索引文件，也可通过 `smem index --rebuild` 或 `smem check --fix` 一键修复。
