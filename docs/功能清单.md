# smem：共享记忆的使用体验

状态：已定稿（下一版设计基线；交付情况见表）。更新：2026-11-21。上游：[需求](需求设计.md)、[原生记忆调研](调研/主流编程助手的记忆.md)。落地：[路线图](roadmap.md)。

用户只管跟当前助手说话。理想的一次交接：在 Claude 里说“这次发版由阿宁放行，以后这个项目都找她”；下周在 Codex 里只说“准备发版交接单”，放行人就填对了。在 Codex 里纠正“现在改由小周放行”，Claude 新会话也用小周。整个过程不要求人记命令、挑文件或重复交代。

## 用户有五件事可做

| 动作 | 用户怎么说 | 助手怎样做 | 当前交付 |
| --- | --- | --- | --- |
| 记住 | “这个项目发版前要找阿宁。”“所有项目都先给我看差异。” | 默认只记本项目；明确跨项目的个人习惯才记全局。任务中有证据、以后还能复用的结论也可顺手记，回复时说一句记到了哪里。 | 已有两层写入和原文去重；能否主动记待实测 |
| 想起 | “准备上线交接单。” | 开工先查；能用就用，在会影响决定时带一行出处。找不到不编，当前资料与旧经验不符时先核对。 | 已有关键词和出处；换说法的查找、常用约定见下节 |
| 纠正 | “以后这个项目由小周放行。” | 找到同项目的旧结论，原位改成新结论。目标明确就办，有两条说得通才追问。另一工具下次查只见现行说法。 | 目前只能手改文件；计划提供统一纠正操作 |
| 忘掉 | “忘掉刚才那条放行人约定。” | 删除明确指向的那一条；不殃及同主题的其他经验。新会话查询不再返回它。 | 目前只能手删；计划提供统一忘记操作 |
| 看看记了什么 | “你记得我的哪些偏好？”“这个项目有什么发布约定？” | 分开列个人和项目，先给短清单，点到某条才给原文和位置，不一次倾倒整个库。 | 目前可打开 Markdown；计划支持按范围列出、查看单条 |

## 三个默认选择

1. **明确说“以后”与只说“这次”分开。** “这一次用 npm”只影响眼前任务，不覆盖惯例。用户明确要求记住时无需二次确认；已验证的项目经验可直接记，不从一次操作推断长期个人偏好。模型猜测、临时待办、私人聊天、账号凭证跳过。个人习惯不复制进团队仓库。项目特例可以和个人默认共存；当前用户要求优先，记忆不能代替操作授权。
2. **让助手换词，人不用。** 工作开始时，一次查询返回两小组：用户明确指定的常用约定、与本次任务相关的经验。常用约定是普通 Markdown 上的可选标记，不新增第三个库；默认概览最多三条，有更多则提示展开。详细经验默认最多五条。完整词组优先，其次看同一条经验中多个实词的命中；证据不足时，助手可用一组别称再查一次（如“上线 / 发版”）。仍无结果就如实说。不引入外部模型，也不承诺能理解所有同义词。
3. **同一事实只保留一份现行说法。** 搜索给出范围、原文和定位。纠正或忘掉前核对刚看到的内容；若别人已改过、同名条目跨范围，或一份主题笔记里有多条相似表述，重新读取、必要时只问一个问题。更正不会自动修改原生笔记。忘掉的作用限于当前共享库；已提交的 Git 历史、旧聊天、其他副本不会随之抹除。

## 如何交给任何助手使用

- 工具说明仍只教“开工先查、持久结论及时记”，完整操作由命令自身说明。一次性初始化、旧记忆迁移提示词照旧。计划让初始化结果直接给出同一条通用用法：即使没有品牌专用接入，只要能接收说明、能运行命令，粘贴这一条就够，无需注册账号。
- 对助手保留 `mem search`、`mem add`；下一版计划增加 `mem update`（纠正）、`mem forget`（忘掉）、`mem list`（分范围浏览）、`mem show`（看原文）。普通偏好随任务查找；只有用户明确说“每次开工都要记得”时，才给该条加常用标记（计划用 `mem add --always`）。开工查询 `mem search --start` 同时取常用约定；普通查询只给相关结果。这里列出的新增用法目前不能执行。
- 所有品牌走相同的本地文件和命令。具有终端权限、能访问同一份授权 Markdown 的助手可以完整接力；只读环境只能回忆。远程环境须自行装命令并同步允许共享的文件。没有终端时给用户可复制的操作或候选文本，不声称已经保存。无需关掉各家的内置记忆，但只有进入共享库的内容才会跨品牌出现。

## “像内置一样好用”的验收

用临时仓库和两个全新助手配置，给每轮分配一个从代码、任务题面都猜不出的放行人。只有写入方知道名字。换助手时不转聊天、不粘答案，接手侧的普通任务不出现“记忆”“搜索”或命令。共享组关掉原生记忆；原生对照组用同品牌的两个新会话，不装 smem，不共用测试目录。记录客户端版本、写完多久可读、是否查了、查到什么、最终交接单用的是什么；共享组仅写对名字却无共享库读取证据，不计通过。

| 场景 | 过关条件（目标，尚无成绩） |
| --- | --- |
| 主动接力 | Claude 写、Codex 用，再对调；每个方向各 5 次，每个方向至少 4 次无需提醒就用对。另用同一工具的原生记忆做对照：保持模型、题面和权限一致，注明原生记忆是否已生成。这个小样本用来发现问题，不代表普遍成功率。 |
| 纠正、忘记 | 对面工具改人后，原工具的新会话只查到新人；忘掉后双方新会话都查不到该约定，邻近笔记仍在。 |
| 范围和误用 | 另一个项目同问不出现该放行人；全局偏好在两个项目都可用。一次性要求不持久化，无关任务不硬套旧结论；无终端时不得声称写入成功。 |
| 不依赖品牌 | 给未配置专用接入、但具有终端权限的另一助手粘贴通用用法。无需改 smem 代码就能读已有结论、写下新结论。记录实测客户端，不外推到没有验证的平台。 |

推进顺序：先用现有版本跑双向接力，分清漏在“没去查”“没命中”还是“查到没用”；随后补齐纠正、忘记和浏览，再用同一套题验收。首轮先跑 Claude Code 和 Codex；接其他品牌复用同一组题，不把“能写说明”计作兼容实测。
